## Behavior

The bot reads Qdrant directly and uses its existing Marqo endpoint/index for query embeddings. It requires no memory API endpoint or running background service. The background dreamer independently consumes Langfuse and writes Qdrant through its own private storage API.

The reader enforces farmer ownership and explicit off settings before reads, hides internal records and identifier metadata, excludes superseded search/list entries, and returns whole saved chunks with bounded continuation. Flags remain program-controlled records, not model-editable metadata. Existing search/list/read tool arguments remain simple and unchanged by the transport move. Memory context and instructions remain conditional; an empty lookup adds no keys-only block. The existing Soil Health Card context is preserved.

## Demo limits

Useful recall is demonstrated, but reliable model behavior is not. The synthetic direct-reader run had nine better, ten similar and one worse answer with memory; some improvements were partial. Stored receipt/submission detail was sometimes left unread; the listing tool was not invoked when instructed; generated summaries occasionally overstated intentions. The unverified scheme claim was a general answer-grounding failure observed in the memory-on arm, not a false scheme name stored in memory or established proof of memory causation.

This supports a supervised demo of the integration and its limits. It does not establish multilingual, multi-farmer production accuracy or coverage of voice/doctor channels. Authentication/rollout policy and background scheduling remain separate work, as requested.

## Proposed PR text

Title: Add optional farmer memory reads from Qdrant

The farmer chat path can now recall earlier conversations through bounded memory context and search/list/read tools. It reads Qdrant directly, using the existing Marqo endpoint for query embeddings; the independent background dreamer is not a live dependency. Farmer ownership, disabled settings, current versions and complete chunk boundaries are enforced in the bot reader.

Memory remains globally off by default. Enabling it requires `QDRANT_URL`, `QDRANT_API_KEY`, `QDRANT_COLLECTION` and matching existing `MARQO_ENDPOINT_URL`/`MARQO_INDEX_NAME`; no `MEMORY_API_URL` is needed. See `docs/memory-dev-demo.md` for deployment defaults and verification. Validation: 41 focused tests passed with the patch applied to latest main; a 20-question paired synthetic replay and live direct-reader isolation/pagination checks completed. Automatic search is a sample, and model compliance with list/detail instructions remains an observed demo limitation.
